4. Google Forms CSV → GoogleFormResponse[] in backend/src/assessments/google-form-csv.ts:
   - Header detection is by column NAME, tolerant of case/whitespace: timestamp ("Timestamp"), email ("Email Address" / "Email address" / "Username"), score ("Score"). All other columns are questions in order. If the form's UI language produced non-English headers, allow the teacher to pass nothing extra — instead detect the timestamp column as the first column and the score column by the value pattern `^\s*\d+(\.\d+)?\s*/\s*\d+(\.\d+)?\s*$` on the data rows; say in your report exactly how detection works.
   - Score "7 / 10" → totalScore 7, and the max 10 becomes totalPoints (all rows must agree, else error). No score column → totalScore null.
   - Timestamps: Google exports local-time strings like "2026/09/27 3:45:12 PM GMT+3" or "9/27/2026 15:45:12"; parse the common forms to ISO; if a row's timestamp cannot be parsed, reject the file with the row number (don't guess).
   - responseId (stable externalId): sha256 of timestamp + normalised email + the row's cells, hex — so re-importing the same file is a no-op and an updated export replaces the set through replaceResults.
   - answers: one per question column, questionId `q${index}` (1-based) and ALSO keep the header text: store `raw: { answers, questions: [{ id, title }] , source: 'csv' }` (extend what is stored in raw; keep `answers` shaped as today so existing readers work). Multi-select answers in Google CSV are joined by ", " — split them into values only when the same column's cells contain ", " AND the column is a checkbox-style question is not knowable; therefore keep the cell as a single value string unless empty. Say so in the report.
   - Caps: ≤ 2 MB, ≤ 2000 rows, ≤ 200 columns; blank rows skipped.
